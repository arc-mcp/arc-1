# Current-build pinned PP workflow, first phase

`current-pp-workflows-v1` extends the existing interactive harness. It is an offline-reviewed
candidate until an independently approved, exact committed source and its actual deployment are
qualified. It does not change production permissions, public admission or the older plans.

The fixed graph is primary CLAS + standalone INCL + consuming PROG in one supplied recorded
package, and secondary CLAS in `$TMP`. Both classes get real method edits; the primary also gets a
changed definition and a substantive test-class include. The test source is compiled/activated,
**never executed**: no ABAP Unit, report/class run, RFC, helper, arbitrary MCP program or SQL.
Program/include sources are updated; the program's symbols are saved and verified active. Fresh
source hashes, deliberate stale-hash refusals, both native creators/changers, metadata state,
active/default sources and exact CTS request/task membership are checked. All text-pool parts are
included in the primary program's cleanup comparison. Cleanup is PROG → INCL → secondary CLAS →
primary CLAS through PP, with separate typed native absence. Request/task entries are observed and
retained; the runner never creates, releases, reassigns or deletes a transport.

## Operator prerequisites and preparation

Root performs all native/cloud/browser work. Before preparing a run:

- Commit and freeze the integrated source; deploy that same revision. Keep a private operator
  deployment receipt with `appOrigin`, `sourceRevision`, `dropletGuid`, `artifactSha256`, `observedAt`.
  These are actual CF/build observations, not evidence generated by this harness. The runner binds
  and rechecks the receipt; it cannot independently attest a running CF droplet.
- Verify the existing recorded package (for example, the known `ZARC1_DEMO`, only after a fresh
  check), a fresh exact modifiable Workbench request and a distinct modifiable task owned by the
  primary SAP developer. Never reuse an old request/task ID from research. Both effective package
  and request policies must authorize this exact context. The server and destination must have
  their repository write gates enabled. Keep `SAP_ALLOW_TRANSPORT_WRITES=false` for this
  recording-only phase and exact request allowlists at both server and destination; do not widen
  them to `*`. The primary still needs raw `read write transports` scopes for recorded repository
  writes. That scope does not enable CTS management or authorize creation of a new request.
- Keep the secondary's existing narrow `$TMP`, `ZARC1*`, CLAS/INTF authorization boundary. Role
  assignment/restoration is operator work; this script never changes SAP or BTP permissions.
- Resolve cleanup prerequisites separately: the retained package cleanup, publication/generated
  cleanup and downstream-safe release route are not operations in this phase. Do not add those
  fixtures by editing command arguments.
- Stop competing SAP/native/CI work and keep the execution host awake. Preserve the before-state
  and operator restoration records. Global SM12 inspection belongs to the operator, not ARC-1.

Use Node **22.21.1**, existing dependencies and the original README's three expected identity
variables, private credentials and fresh persistent `ARC1_QUALIFICATION_STATE_DIR`. The target is
fixed at `PR1142/001`; read-only destination checks use `/A4H/001/mcp` on the existing isolated app.

Install the actual deployment receipt as owner-only `deployment-receipt.json` in that root.
The native read worker has only `preflight`, `identity` and `absence` modes; it cannot lock, delete
or repair. An operator may run its fixed `preflight all <fresh lowercase UUID>` through the existing
`nativeCheck('current-workflow-native.mts', 'preflight', 'all')` primitive before controls. The live
qualifier always repeats the four typed absence reads and exact request/task check before writes.
The worker reads credentials only after source/configuration/argument validation, uses fixed GETs,
a 60-second deadline, 32 sends and a shared 512-KiB decoded-response budget. Its native responses,
errors and source hashes remain private. Generic/HTML/foreign-namespace 404s are uncertain.

The operator attests the actual filters and complete zero results. The runner checks chronology,
private file ownership, bounded bytes, JPEG boundary signature and exact hashes; this is **not**
image decoding or visual verification. Controls must be newer than preparation and under five
minutes old at the first possible mutation. Their receipt and bytes are rechecked during the run;
forward work has a fixed eight-minute deadline. A new screenshot is required for a later attempt,
which must use a separately prepared root and fresh names.

Execute once, only after independent source review and the operator's execution prerequisites:

```json
{"command":"qualify","plan":"current-pp-workflows-v1"}
```

The claim is permanent, even on refusal or pre-mutation failure. There is no resume/retry switch.
The actual refreshed schemas must support every planned input before any owner is created.
All three actors must have a `SAPTransport.get` catalog and none of the six management actions
(`create`, `release`, `release_recursive`, `delete`, `reassign`, `remove_object`). The primary's
exact request read is also checked against the full schema. Both writer tools (`SAPWrite` and
`SAPActivate`) must be present for writers and absent for the reader. Catalog visibility does not
prove native request/task membership; the separate exact readback checks remain mandatory.

The 2026-11-03 run against revision `5aa7533d6bf71388318510abeae630483e33ba53` stopped with
`CURRENT_TRANSPORT_CATALOG_MISMATCH` before any fixture attempt: the old runner incorrectly
expected `create` from raw transports scope. That failed result and consumed claim remain intact;
this correction requires a separately prepared run and reviewed source/deployment binding.
Each mutation intent is journaled before HTTP; replies and uncertain transport failures are retained.
Source, manifest, deployment/control receipts, cancellation and deadlines are checked at the client
send boundary. Server adapters retain their normal identity/package/CTS/lock and no-replay controls.
The independent native reader is Basic **read-only** evidence; every mutation is via the verified PP
MCP session. `SYSTEM.user` is not used as proof of mapped SAP identity.

Failure stops forward work and deletion. Successful deletes remain recorded if a later independent
absence read fails. Do not erase/reuse the claim, rerun the old graph or invoke the legacy native
cleanup helper. Inspect residuals and obtain a separately reviewed exact recovery if required.
On completion, capture and inspect fresh SM12 suffix/both-user controls, audit all receipts/claims and
record a complete private file ledger before restoring app/role settings. A green workflow result
is not that final operator audit and always returns `qualifiedForMerge: false`.

Public DELETE has no optimistic source-hash argument. The fresh native comparison before PP DELETE
is an observation, not an atomic SAP lock across the following request. Operator non-overlap is
therefore essential; the harness does not claim to protect an intervening external editor. Native
source/default/active reads are likewise observed sequences, with before/after metadata checks.

## What this phase does not qualify

Reader, destination-without-write-opt-in, aggregate and compatibility routes get actual catalogue
and hidden-update denials on a declared owned sentinel. Shared Basic remains explicitly outstanding
because the current app has its Basic exception disabled; do not guess a route or enable it here.
The phase does not stand in for FUGR/FUNC, metadata/DDIC, six later DDIC/SDO/document groups, RAP/
batches/publication, move/API, all six CTS management actions, trace/settings/FLP, other releases,
final deployment review or CI. Existing native evidence may only be retained through the accepted
component comparison. It adds one substantive current-build two-writer PP/recording cut, not a scope
reduction or a Cartesian family × user × release requirement.

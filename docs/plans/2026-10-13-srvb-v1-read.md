# Service-binding XML reads on 7.55 (#991)

The report shows a binding GET rejecting v2 XML with 406 while accepting v1. Reads,
publish/unpublish package checks, and publish-failure readback all request v2. The
shared HTTP retry currently tries generic XML, which does not select the required
service-binding representation.

Plan: add a v1 fallback to the existing one-retry negotiation path, scoped to GETs
of individual binding metadata with the exact v2 Accept. Keep v2 preferred and
leave write Content-Type, other resources, authorization, and package checks alone.
No release probe, new setting, or extra handler-level retry is needed.

Review: this covers all three consumers at their shared HTTP boundary. Regression
tests must exercise v1-only reads, both package guards, and failure readback, plus
denied/missing package evidence and a failed retry. Verify real v1 metadata and
publish/unpublish on available systems; no 7.55 system is available locally.

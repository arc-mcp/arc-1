# PR #772: second review assessment and verification

Reviewed against `5f7ea999`. The [follow-up plan](../plans/2026-09-10-atc-batch-rereview.md)
was reviewed before implementation. This assessment separates reproduced behavior,
the chosen completeness contract, and test-coverage gaps.

## Decisions

| Review item | Assessment and action |
|---|---|
| Child findings disappear after selection filtering | Confirmed with constructed SAP responses. FUGR/F plus two FUGR/FF rows lost five priority-1 findings; PROG plus PROG/I rows lost four. Keep records outside the supported batch-root contract, including FUNC/INCL and unknown enclosing types. Their findings retain type/name, source locations and worklist provenance. Mark the run incomplete and coverage counts unknown because these rows lack a general, verified parent association. Continue excluding other supported roots and verification overlap. |
| One contradictory URI makes the run incomplete | Reproduced, retained intentionally. This is the same run-scoped completeness decision accepted in the first review's item 8. A matching object's observed findings remain visible; its verified total becomes unknown when the worklist is inconsistent. The new mixed-good/bad test proves that findings are retained and no retry occurs. Do not equate fewer certified counts with discarded findings. Per-object certification and selective recovery would require a broader evidence model. |
| TABL rejects source/main | Confirmed. Accept exact table and structure source/main resources, alongside their metadata and ATC R3TR roots. Both source forms already exist in `AdtClient.getTable`/`getStructure`. No new metadata request or descendant wildcard. DOMA/DTEL/SRVB remain metadata-only. |
| Test gaps | Add independent ordinary-network, caller-abort and network-AbortError tests; SAP-reported Unicode identity tests; SRVB root and source rejection; and DEVC with the otherwise-valid name Z_PACKAGE. Add child retention/completeness tests for initial and verification runs, unknown enclosing types, same-named function/group identities and empty child records. |
| Historical red-test claim | The saved initial development log records 23 failed / 56 passed. The final assertions evolved before commit, so that count should not describe a replay of the later committed tests against old source, nor label every passing case pre-existing. Clarified the first assessment and PR wording. The second review's 20-failure replay is a different test snapshot. |
| ADT imports a handler utility | A real layering concern, but the imported module is a pure leaf and the review found no cycle. Retain the shared normalizer for this narrow fix. Moving the object-type utilities is separate structural work; duplicating aliases or adding a dependency-injection interface would increase drift/complexity. |

This does not implement parent rollups or source-location ownership guesses. Even
an unrelated unsupported record can conservatively make the run incomplete. That
is the explicit tradeoff for preserving possible child findings without extra SAP
lookups. Normal supported-root batches keep their existing counts and response
layout; no scheduler, retry loop, cache or new response grouping is introduced.

## Final review

The production diff is confined to ATC batch reconciliation and known TABL URI
equivalence. The lifecycle executor, 20-entry cap, variant confirmation, at most
one verification and original deadline are unchanged. Unassigned rows now stop
verification and cannot produce a verified clean count. Unsupported identities
stay distinct from their possible parents, and their observed findings survive.
The existing supported-root superset and overlap tests still pass. New URI tests
cover both accepted exact resources and rejected metadata-only source resources.
No tool schema or snapshot changes are needed.

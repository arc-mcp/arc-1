## Final dispatch correction after the first review

The [verbatim first review](2026-11-03-native-declarative-v5-review1-verbatim.md) refused
`d76b01cdba79e6e26d71b55d73c3a1da344a0e64`: the observer checked immutable bindings before
asynchronous transport preparation, and V5 treated conservative request intent as a mutation
handoff. In particular, source/history drift or baseline expiry during CSRF loading could permit
the first mutation. No V5 phase may run until the corrected exact source receives renewed review.

The correction retains the original attempt allowance and invokes the fixed request/source/history/stop
validator at the actual direct or Connectivity transport boundary, after queue, CSRF, bearer and proxy
token waits. The original synchronous allowance/proof runs first, the native proof follows, and the
effective deadline/cancellation check runs after both. No counters, response allowance, no-replay
policy, outer lifetime or independently bounded owning UNLOCK/session-close allowance is renewed.

An optional budget notification records the actual HTTP method handed to the dispatcher. A mutation's
HEAD/GET CSRF bootstrap therefore cannot end V5 baseline freshness. Only the first non-bootstrap,
non-transport-check mutation handoff does so; immutable source/history/receipt and stop checks remain.
This is handoff/attempt evidence, not server success. Request-intent records and uncertain outcome
tracking remain conservative even when a later local proof prevents dispatch. Historical phase
coordinators retain their existing intent semantics; historical fixture graphs, roots, claims and
proof bytes are unchanged.

The original isolated phase regressions now prevent both CSRF-window failures. The original two
CREATE microtask probes were rerun unchanged and still observe one CREATE: instrumentation shows
the native MockAgent CREATE and handoff precede their scheduled fault microtask when there is no
queue/authentication wait. That is a post-dispatch fault, not a preventable pre-dispatch change. The
same actual-driver probes with the real `adtSemaphore` cross an asynchronous boundary, then refuse
both source drift and stop before CREATE; valid lifecycle and own-cleanup controls still pass. Raw
original failures, diagnostic ordering and corrected queue controls are retained in the external
correction report for independent evaluation. No artificial yield is added to change that ordering.

The first independent review also recorded a test-isolation incident: activation's separate long-operation
dispatcher escaped its initial global MockAgent and obtained an unexpected HTTP 401 using synthetic

review retains the evidence limits. Corrected probes use `.invalid` origins, mock Agent and Connectivity

configuration was rerun for this correction.

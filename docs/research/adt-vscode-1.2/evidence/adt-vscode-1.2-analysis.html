ADT for VS Code 1.2

The strongest story is the expansion of everyday ABAP workflows: transports, data inspection, version history, diagnostics and more capable AI tooling.

Version 1.1 broadened the objects developers could work with. My assessment is that 1.2 makes it more practical to stay in VS Code through the surrounding development cycle. That is a stronger, more defensible LinkedIn angle than declaring complete Eclipse parity.

What changed and why it matters

AreaChange in 1.2Practical significance and limits
Transport OrganizerA dedicated Explorer view organizes requests, tasks and objects. New actions include owner changes, adding users or objects, filtering by user, opening changes and releasing requests or tasks.Transport work becomes part of the editor workflow. Creating and finding transports already existed; the new organizer and release actions are the meaningful delta. Changing the view’s destination should not be described as changing a transport’s import target. SAP documentation; local manifest comparison.
SQL NotebookNew .abapsql notebooks combine SQL code cells and Markdown. They support syntax checking, query results and statistics, and configurable row limits.Save repeatable data investigations with explanations. SAP documents a default of 100 rows and a maximum of 100,000, plus exports to delimited text, HTML, XML and ABAP value statements. The installed commands also expose per-cell system and row-limit selection. This does not establish unrestricted database administration or data modification support. SAP documentation.
ABAP TimelineA dedicated history view shows object revisions with version, transport and author details. Compare a revision with its predecessor, another selected revision, or the latest version.Useful for understanding regressions and reviewing changes. SAP documents that the latest version is editable in its comparison view. This is ABAP object history; it is not evidence of a new Git integration. SAP documentation.
ABAP FeedsA new panel exposes backend-provided feeds such as runtime errors, unit-test runs, ATC findings and Gateway errors. Filters can use templates or custom expressions.Diagnostics can be investigated beside source. Available feeds depend on the selected backend. Entries can expose detail views; refresh is manual, so do not call it live monitoring. SAP documentation.
Dictionary activation logA new command and log document type expose technical activation information for Dictionary and supported CDS objects.Helps explain failed activation beyond the headline error. It complements the debugger; it is not a new debugger capability merely because the README groups it nearby. Local command and language registrations; SAP documentation.
Source-code searchSystem-side text search across source-based repository objects, with a new Search in ABAP Source Code... command.Addresses investigation of existing codebases. Distinguish it from object-name search and local filesystem search. Local command registration; release notes.
ATC exemptionsRequest an exemption from a finding in the editor, supplying validity, reason, justification and transport information where applicable.The documented cloud workflow creates a transportable CHKE object. It applies to the latest ATC result and still requires approval; it does not repair the underlying finding. New MCP tools request exemptions and identify permitted approvers. SAP documentation.
Service consumptionCreate service consumption models for OData, RFC and Web Services using local metadata files.SAP documents EDMX for OData, XML for RFC and WSDL for Web Services. This extends integration development within VS Code; it does not mean arbitrary endpoints can be consumed without metadata and backend setup. SAP documentation.
Swagger service testingLaunch Swagger UI from service bindings to test OData V2/V4 services.Useful for RAP service checks. The V4 documentation excludes custom request headers and verbs outside GET, PUT, POST and DELETE; PATCH is therefore outside the documented tool scope. Avoid presenting it as a complete replacement for an API client. SAP documentation.
Custom system connectionsThe RFC destination wizard accepts a user-specified system without SAP Logon Pad.Connection details can be entered directly, including server, instance, client and optional SAProuter/SNC settings. RFC itself was already present in 1.1.2. The new story is independent configuration of the system connection. SAP documentation.
Solution Manager connected systemsThe release notes add object creation and modification in Solution Manager connected systems.This may remove a blocker in managed landscapes. Do not expand this narrow statement into a claim of full ChaRM workflow support. Release notes.

Repository coverage

The installed README expands coverage to packages, message classes, data elements, BAdI implementations and enhancement spots, technical table settings, service consumption models, additional CDS artifacts, launchpad objects, application logs and transactions. These additions make ordinary application work more self-contained in VS Code.

SAP’s 1.2 list additionally names business configuration maintenance objects (SMBC), application job templates/catalog entries (SAJT/SAJC), software component relations (SWCR), predefined field enabling (PCFN) and IAM apps (SIA6). It also includes scalar function definitions (DSFD), entity indexes (DTIX), static/dynamic caches (DTSC/DTDC), and launchpad descriptor/page/space objects (UIAD/UIPG/UIST). SAP release notes.

Two wording traps: ENHS appears under both BAdI definitions and enhancement spots, so counting list entries as distinct new object types inflates the number. Your previous post already mentioned XSLT, and 1.1.2 contains its language registration. Describe 1.2’s documented transformation creation workflow specifically rather than saying that XSLT support first arrives now.

The AI and MCP changes

The practical advance is that an agent has more explicit ways to locate an object, obtain its source, modify it when enabled, check it and inspect diagnostic evidence. These are capabilities for building workflows; their presence does not demonstrate autonomous end-to-end correctness.

Tool names and scope: SAP MCP tools reference. Local 1.2 plugin registrations independently confirm additions for file access, search, checks, feeds, exemptions and object actions.

Access restrictions are a major part of the release. They default to enabled. Destination rules restrict reads and writes; package rules restrict object creation and modification within allowed destinations. Reading other packages in an allowed destination remains possible. The shipped default allowlists are empty, and the edit-file tool defaults to disabled. This deserves a configuration review when adopting the new MCP behavior. SAP setup documentation.

Licensing and migration: SAP labels object explanation and documentation search as requiring token consumption/additional costs. Several mechanical tools are marked as not requiring those costs, but SAP separately conditions MCP support on a valid Joule for Developers ABAP AI capabilities license. “No additional tool token cost” is not equivalent to “everything is license-free.” The reference also warns that tool names changed, so existing agent instructions may need updates. Availability and technical qualifications

Installing the client does not make every backend feature available. The 1.2 release table often references ABAP environment 2611 and S/4HANA Cloud Public Edition 2702; on-premise/private-cloud ranges vary by feature. Some listed backend releases are later than this analysis date. Check the applicable feature and backend combination before promising availability. SAP release matrix.

The live release table also links its source-search entry to a transformation page. Its roadmap and release table give differing ranges for some entries, including static caches. For the post, the defensible qualification is “availability depends on backend release”; an exact compatibility promise needs system-specific verification.

How to frame the LinkedIn post

Your previous post works because it combines concrete capabilities with a measured Eclipse comparison. Keep that credibility, but make the first two lines carry the story. Lead with the earlier verdict, then show which daily workflows now challenge it. Short feature paragraphs give readers more entry points than a dense list of repository types.

The closing question asks for a specific remaining workflow, which gives ABAP developers something useful to discuss. Avoid unsupported performance numbers, universal compatibility, a claim that AI was first introduced in 1.2, or a guarantee that the post will go viral.

“Not ready to replace Eclipse.”

That was part of my verdict on ADT for VS Code 1.1.

I just updated to 1.2.0, and this release tackles several of the everyday workflows behind that verdict.

The additions that stand out:

→ Transport Organizer: manage requests and tasks, inspect changes, and release transports from VS Code.

→ SQL notebooks: run queries, inspect results, and save SQL alongside Markdown notes.

→ ABAP Timeline: inspect an object’s version history and compare revisions.

→ Troubleshooting: access backend feeds for runtime errors, ATC findings and Gateway errors, plus Dictionary activation logs.

→ More repository coverage: packages, data elements, message classes, BAdIs, service consumption models and Fiori launchpad objects.

There is also a substantial ABAP + AI update: new MCP tools for finding, reading, checking and explaining objects, querying runtime feeds, and opt-in source editing. Access can now be restricted by destination, with object changes limited to selected packages.

Source-code search, Swagger testing for OData V2/V4 services, and custom RFC connections without SAP Logon Pad round out the release.

My takeaway: 1.2 gives us more of the surrounding workflow that makes an editor useful for daily ABAP work.

Feature availability still depends on the backend release, and some AI capabilities have additional licensing requirements. I would still judge Eclipse replacement against the work your team actually does.
